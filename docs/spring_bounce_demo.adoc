= Spring Bounce Demo Documentation

The Spring Bounce Demo demonstrates impulse-momentum transfer through a user-controlled moving wall that acts as a spring. This interactive simulation illustrates how moving surfaces transfer momentum to objects and how velocity can be modified through controlled collisions.

== Overview

In this demo, a ball falls under gravity and bounces on a horizontal surface. Users can move the bottom wall upward during the simulation, imparting additional upward velocity to the ball, simulating the effect of a spring mechanism. This provides hands-on experience with impulse-momentum transfer and real-time physics control.

== Key Physics Concepts

=== Impulse-Momentum Theorem

The fundamental principle demonstrated in this demo is the impulse-momentum theorem.

[latexmath]
++++
\vec{J} = \Delta \vec{p} = m\Delta \vec{v}
++++

Where:
* **J** = Impulse (change in momentum)
* **p** = Momentum (mass × velocity)
* **m** = Mass
* **v** = Velocity

**Key Insight**: When a moving wall collides with a ball, the wall transfers some of its momentum to the ball.

=== Velocity Transfer Mechanism

Unlike static collisions where only direction changes, moving surfaces can modify the magnitude of velocity.

**Standard Bounce (Static Wall)**:
[latexmath]
++++
v_{new} = -v_{old} \times e
++++

Where *e* is the coefficient of restitution.

**Spring Bounce (Moving Wall)**:
[latexmath]
++++
v_{new} = v_{reflected} + v_{wall} \times k
++++

Where *k* is the spring coefficient (1.5 in this demo).

**Code Implementation**:
[source, python,linenums]
----
# src/views/demos/spring_bounce_view.py:90-92
if colliding_object == moving_wall and wall_velocity.y < 0:
    # Spring effect: transfer wall velocity to ball
    self.ball.velocity.y += self.wall_velocity.y * 1.5
----

=== Hooke's Law (Simplified)

While the demo doesn't implement true spring physics, the effect is conceptually similar to Hooke's Law.

[latexmath]
++++
\vec{F} = -k\vec{x}
++++

Where:
* **F** = Restoring force
* **k** = Spring constant
* **x** = Displacement from equilibrium

**In Our Demo**:
* The "spring" is the user-controlled wall
* Instead of Hooke's Law, we use direct velocity transfer
* The coefficient 1.5 simulates a "bouncy" spring

=== Vector Inversion

Before applying the spring effect, the normal vector is inverted to ensure it points away from the collision surface.

**Why Invert?**
The reflection formula expects the normal to point outward from the surface, but the calculated normal points toward the ball.

[source, python,linenums]
----
# src/views/demos/spring_bounce_view.py:83-85
# Invert normal to point outwards from collision surface
normal *= -1

# Then calculate reflection
reflected = self.ball.velocity - 2 * self.ball.velocity.dot(normal) * normal
----

=== Collision Detection with Moving Objects

The demo handles collisions differently for the moving wall versus static objects.

**Detection Strategy**:
[source, python,linenums]
----
# src/views/demos/spring_bounce_view.py:71-89
new_x = self.ball.x + self.ball.velocity.x
new_y = self.ball.y + self.ball.velocity.y
would_collide, colliding_object = self.board.would_ball_collide(
    self.ball, new_x, new_y
)

if would_collide and colliding_object:
    normal = colliding_object.get_normal(self.ball)
    normal *= -1  # Invert for outward normal

    # Calculate reflection
    reflected = self.ball.velocity - 2 * self.ball.velocity.dot(normal) * normal
    self.ball.velocity = reflected * self.ball.bounciness

    # Apply spring effect if it's the moving wall
    if colliding_object == self.moving_wall and self.wall_velocity.y < 0:
        self.ball.velocity.y += self.wall_velocity.y * 1.5
----

== User Controls

### Keyboard Input

| Key | Action | Effect |
|-----|--------|--------|
| **UP Arrow** (Hold) | Move wall upward | Imparts upward impulse to ball on collision |
| **DOWN Arrow** (Hold) | Move wall downward | Moves wall away from ball |
| **Release Keys** | Stop wall movement | Wall stays in position |

### Control Strategy

**Maximum Height Launch**:
. Wait for ball to reach its lowest point (just before bouncing)
. Press and hold UP arrow
. Time the wall movement to collide with ball at peak compression
. Ball receives maximum impulse
. Release UP arrow after ball launches

**Soft Bounce**:
. Press UP arrow gently (short press)
. Collide with ball when it has low downward velocity
. Ball receives smaller impulse
. Good for controlled movement

**Sequence of Bounces**:
. Launch ball high with wall
. Wait for ball to fall
. Time second bounce for medium height
. Repeat for rhythmic bouncing pattern

== Mathematical Analysis

### Spring Effect Calculation

When the moving wall collides with the ball:

**Scenario**: Wall moving up at -5 m/s, ball moving down at 5 m/s

1. **Standard Reflection** (no wall movement):
[latexmath]
++++
v_{reflected} = -5 \times 0.8 = -4 \text{ m/s}
++++

2. **Apply Spring Effect**:
[latexmath]
++++
v_{new} = v_{reflected} + v_{wall} \times k
v_{new} = -4 + (-5) \times 1.5
v_{new} = -4 - 7.5
v_{new} = -11.5 \text{ m/s}
++++

3. **Result**: Ball bounces upward at 11.5 m/s instead of 4 m/s (187% increase!)

### Energy Transfer

**Kinetic Energy Before Collision**:
[latexmath]
++++
E_{initial} = \frac{1}{2}mv^2 = \frac{1}{2}(1)(5)^2 = 12.5 \text{ J}
++++

**Kinetic Energy After Spring Bounce**:
[latexmath]
++++
E_{final} = \frac{1}{2}mv^2 = \frac{1}{2}(1)(11.5)^2 = 66.1 \text{ J}
++++

**Energy Increase**: 66.1 - 12.5 = 53.6 J (428% increase!)

*Note: This violates energy conservation because we're adding energy from the user-controlled wall.*

### Velocity Transfer Efficiency

The spring coefficient (1.5) determines how efficiently momentum is transferred.

* **k = 1.0**: 100% of wall velocity transferred
* **k = 1.5**: 150% of wall velocity transferred (current setting)
* **k = 2.0**: 200% of wall velocity transferred (super spring)

**Optimal Range**: 1.0 to 2.0 for realistic spring-like behavior

### Timing Analysis

For maximum height, time the wall collision when the ball's downward velocity is highest.

**Optimal Timing**:
. Ball accelerates downward under gravity
. Maximum downward velocity just before hitting wall
. Wall moves up, collides with ball at this moment
. Maximum momentum transfer occurs

**Suboptimal Timing**:
. Ball already bouncing upward (away from wall)
. Wall collides with ball moving in same direction
. Reduced momentum transfer or no transfer

### Momentum Conservation

**Without Wall**:
[latexmath]
++++
p_{before} = mv = 1 \times 5 = 5 \text{ kg·m/s}
p_{after} = -mv = -1 \times 4 = -4 \text{ kg·m/s}
\Delta p = -4 - 5 = -9 \text{ kg·m/s} \text{ (energy loss)}
++++

**With Moving Wall**:
[latexmath]
++++
p_{wall} = m_{wall}v_{wall} \text{ (implied large mass)}
\Delta p_{ball} = p_{after} - p_{before}
\Delta p_{ball} = -11.5 - 5 = -16.5 \text{ kg·m/s}

\text{Momentum gained by ball} = 16.5 - 4 = 12.5 \text{ kg·m/s}
\text{Momentum lost by wall} = \Delta p_{ball} - \Delta p_{no\_wall}
\text{Momentum lost by wall} = -16.5 - (-9) = -7.5 \text{ kg·m/s}
++++

The wall loses momentum equal to the impulse it imparts to the ball.

### Physics Principles Illustrated

1. **Newton's Second Law**:
[latexmath]
++++
\vec{F} = m\vec{a}
++++
The force from the wall creates an acceleration that changes the ball's velocity.

2. **Impulse-Momentum Theorem**:
[latexmath]
++++
\vec{J} = \Delta \vec{p}
++++
The impulse from the wall changes the ball's momentum.

3. **Work-Energy Principle**:
[latexmath]
++++
W = \Delta E
++++
The wall does work on the ball, increasing its kinetic energy.

4. **Kinematics**:
Position, velocity, and acceleration relationships are clearly observable in real-time.

5. **Hooke's Law (Conceptual)**:
While not mathematically identical, the behavior is conceptually similar to a spring.

== Code Implementation

### Key Methods

**SpringBounceView.update()**:
[source, python,linenums]
----
def update(self):
    '''Update game state with spring physics.'''
    # Update wall position
    self.moving_wall.rect.y += self.wall_velocity.y

    # Apply gravity
    self.ball.add_force(Vector2(0, GRAVITY * self.ball.mass))

    # Predict collision
    new_x = self.ball.x + self.ball.velocity.x
    new_y = self.ball.y + self.ball.velocity.y
    would_collide, colliding_object = self.board.would_ball_collide(
        self.ball, new_x, new_y
    )

    # Handle collision
    if would_collide and colliding_object:
        normal = colliding_object.get_normal(self.ball)
        normal *= -1  # Invert for outward normal
        reflected = self.ball.velocity - 2 * self.ball.velocity.dot(normal) * normal
        self.ball.velocity = reflected * self.ball.bounciness

        # Spring effect
        if colliding_object == self.moving_wall and self.wall_velocity.y < 0:
            self.ball.velocity.y += self.wall_velocity.y * 1.5
    else:
        # No collision, update normally
        self.board.update()
        self.ball.update()
----

== Advanced Topics

### Variable Spring Coefficient

Make the spring effect depend on collision velocity:

[source, python,linenums]
----
def get_spring_coefficient(self, ball_velocity, wall_velocity):
    '''Calculate dynamic spring coefficient.'''
    relative_velocity = abs(ball_velocity.y - wall_velocity.y)

    # Higher velocity = more efficient transfer
    if relative_velocity > 10:
        return 2.0  # Very bouncy
    elif relative_velocity > 5:
        return 1.5  # Normal bouncy
    else:
        return 1.0  # Less bouncy

# In collision handling
spring_k = self.get_spring_coefficient(
    self.ball.velocity.y,
    self.wall_velocity.y
)
self.ball.velocity.y += self.wall_velocity.y * spring_k
----

== Troubleshooting

### Ball Doesn't Launch High

**Symptoms**: Ball bounces normally even when wall is moving

**Causes**:
* Wall moving in wrong direction
* Timing incorrect (ball moving away from wall)
* Spring coefficient too low

**Solutions**:
[source, python,linenums]

# Verify wall_velocity.y < 0 in collision check
if self.wall_velocity.y < 0:  # Wall moving UP
    # Apply spring effect

### Ball Passes Through Wall

**Symptoms**: Ball goes through moving wall without bouncing

**Causes**:
* Wall moving too fast (tunneling)
* Collision detection misses moving objects
* Wall and ball overlap significantly

**Solutions**:
[source, python,linenums]

                            min(max_wall_speed, self.wall_velocity.y))

# Improve collision detection for moving objects

    # Check multiple positions along wall path

        test_y = self.moving_wall.rect.y + i * (1 if self.wall_velocity.y > 0 else -1)
        # Check collision at test_y
        # ...
----
