== Key Physics Concepts

=== 1. Newtonian Mechanics

The simulation implements classical mechanics based on Newton's laws of motion:

**Newton's Second Law: F = ma**

[source, python,linenums]
----
# src/objects/ball.py:103-105
acceleration = total_force / self.mass
----

This fundamental equation governs all motion in the simulation. Forces are accumulated and then converted to acceleration based on the object's mass.

=== 2. Force Accumulation System

Multiple forces can act on objects simultaneously:

[source, python,linenums]
----
# src/objects/ball.py:98-101
total_force = Vector2(0, 0)
for force in self.forces:
    total_force += force
----

This allows for complex interactions like gravity, collision forces, and user input to be combined naturally.

=== 3. Euler Integration

The simulation uses Euler integration for updating position and velocity:

**Velocity Integration: v = v₀ + a·Δt**

[source, python,linenums]
----
# src/objects/ball.py:107-109
self.velocity += acceleration * Clock.dt
----

**Position Integration: x = x₀ + v·Δt**

[source, python,linenums]
----
# src/objects/ball.py:60-63
self.x += self.velocity.x
self.y += self.velocity.y
----

=== 4. Collision Detection and Response

The simulation implements elastic collisions with energy loss through the coefficient of restitution.

**Vector Reflection Formula: R = J - 2(J·N)N**

[source, python,linenums]
----
# src/views/demos/bumper_view.py:147-148
reflected = self.ball.velocity - 2 * self.ball.velocity.dot(normal) * normal
self.ball.velocity = reflected * self.ball.bounciness
----

Where:
- R = reflected velocity vector
- J = incident velocity vector
- N = surface normal vector
- bounciness = coefficient of restitution (0 to 1)

=== 5. Fixed Timestep Physics

To ensure stable and reproducible physics, the simulation uses a fixed timestep:

[source, python,linenums]
----
# src/utils/time.py:35
Clock.dt = 1.0 / self.frequency  # Fixed physics timestep
----

The accumulator pattern handles variable frame rates while maintaining physics stability:

[source, python,linenums]
----
# src/utils/time.py:62-66
self._accumulator += Clock.vdt
while self._accumulator >= Clock.dt:
    self._update_func()  # Physics update
    self._accumulator -= Clock.dt
----

== Mathematical Operations

=== Vector Mathematics

The simulation extensively uses 2D vector operations:

[source, python,linenums]
----
# Vector operations used throughout the codebase
vector_addition = v1 + v2
vector_subtraction = v1 - v2
scalar_multiplication = v * scalar
vector_normalization = v.normalize()
dot_product = v1.dot(v2)
----

=== Normal Vector Calculations

Different collision surfaces require different normal vector calculations:

**Horizontal Walls:**
[source, python,linenums]
----
# src/objects/horizontal_wall.py:37-52
dy = ball.rect.centery - self.rect.centery
return Vector2(0, 1) if dy < 0 else Vector2(0, -1)
----

**Vertical Walls:**
[source, python,linenums]
----
# src/objects/vertical_wall.py:37-52
dx = ball.rect.centerx - self.rect.centerx
return Vector2(1, 0) if dx < 0 else Vector2(-1, 0)
----

**Circular Objects:**
[source, python,linenums]
----
# src/objects/bumper.py:60-77
direction = Vector2(ball.rect.center) - Vector2(self.rect.center)
if direction.length() == 0:
    return Vector2(0, 0)
return direction.normalize()
----

== Force Types

=== Gravitational Force

Gravity is the primary force acting on all objects:

[source, python,linenums]
----
# src/views/game_view.py:125-127
self.ball.add_force(Vector2(0, GRAVITY * self.ball.mass))
----

=== Inclined Plane Physics

The board can be tilted, modifying the effective gravity:

[source, python,linenums]
----
# src/views/game_view.py:126-127
self.ball.add_force(Vector2(0, -GRAVITY * (1 - self.board.inclination) * self.ball.mass))
----

=== Wind Force

The wind force is simulated using a particle system. Each particle carries a small amount of momentum and transfers it to the ball upon collision.

**Code Implementation:**
[source, python,linenums]
----
# src/views/demos/wind_simulation_view.py:73-75
if pygame.sprite.collide_circle(self.ball, particle):
    force = particle.velocity.normalize() * 0.1
    self.ball.add_force(force)
----

=== Collision Forces

Collision forces are handled through impulse-based collision response using the reflection formula.

== Energy and Momentum

=== Coefficient of Restitution

The bounciness parameter controls energy loss in collisions:

[source, python,linenums]
----
# Energy loss in collisions
ball.velocity = reflected * ball.bounciness
----

Where bounciness ranges from 0 (perfectly inelastic) to 1 (perfectly elastic).

=== Conservation of Momentum

The collision system preserves momentum in the collision normal direction while allowing energy loss through the coefficient of restitution.

== Performance Considerations

=== Collision Detection Optimization

The simulation uses pygame's built-in collision detection for efficiency:

[source, python,linenums]
----
# src/objects/board.py:92-109
collisions = pygame.sprite.spritecollideany(ball, self.obstacles)
----

=== Fixed Timestep Benefits

- **Stability**: Prevents physics instability from variable frame rates
- **Reproducibility**: Same inputs always produce same outputs
- **Performance**: Allows multiple physics updates per frame if needed
