= Gravitational Force Physics Implementation

This document explains how gravitational force is applied to the ball in the particle pinball simulation, covering the physics calculations, scaling factors, and integration methods used.

== Physics Constants and Scaling

The simulation uses real-world physics constants with appropriate scaling for visualization:

[source,python]
----
# Real-world to pixel scale (pixels per meter)
PIXEL_PER_METER = 100

# Time scale factor (simulation speed)
time_scale = 1.0

# Frame rate for physics calculations
FPS = 60
DT = 1.0 / FPS  # Time step in seconds

# Forces
GRAVITY = 9.81  # m/s² (Earth's gravitational acceleration)
----

* `PIXEL_PER_METER = 100`: Converts real-world meters to screen pixels (1 meter = 100 pixels)
* `time_scale = 1.0`: Controls simulation speed (1.0 = real-time, > 1.0 = fast forward, < 1.0 = slow motion)
* `DT = 1/60`: Time step for physics calculations (16.67ms per frame at 60 FPS)
* `GRAVITY = 9.81`: Standard Earth gravity in m/s²

== Gravitational Force Application

Gravitational force is applied in the `FallingBallView.update()` method:

[source,python]
----
# Apply gravitational force: F = mg
self.ball.add_force(Vector2(0, GRAVITY * self.ball.mass))

# Apply board inclination effect
self.ball.add_force(Vector2(0, -GRAVITY * (1 - self.board.inclination) * self.ball.mass))
----

=== Force Calculation

The gravitational force follows Newton's second law: **F = mg**

* `GRAVITY * self.ball.mass`: Calculates the downward gravitational force
* `(1 - self.board.inclination)`: Reduces effective gravity based on board tilt
* `Vector2(0, ...)`: Force is applied in the negative Y direction (downward)

=== Board Inclination Effect

The board's `inclination` property (0.0 to 1.0) modifies the effective gravity:

* `inclination = 1.0`: Full gravity (vertical board)
* `inclination = 0.5`: Half gravity (45-degree tilt)
* `inclination = 0.0`: No gravity (horizontal board)

This simulates the effect of tilting a pinball machine, where the ball's apparent weight changes with the board angle.

== Force Integration Process

The ball's physics engine processes forces through a three-step integration:

=== Step 1: Force Accumulation

[source,python]
----
def apply_forces(self):
    # Sum all forces acting on the ball
    total_force = Vector2(0, 0)
    for force in self.forces:
        total_force += force
----

All forces (gravity, collisions, user input) are summed into a single resultant force vector.

=== Step 2: Acceleration Calculation

[source,python]
----
# Calculate acceleration using Newton's second law: F = ma
# Therefore: a = F/m
acceleration = total_force / self.mass
----

Acceleration is calculated using Newton's second law, dividing the total force by the ball's mass.

=== Step 3: Velocity Update

[source,python]
----
# Update velocity using Euler integration: v(t+Δt) = v(t) + a(t)Δt
self.velocity += acceleration * DT * time_scale
----

Velocity is updated using Euler integration with proper time scaling:

* `acceleration * DT`: Applies acceleration over the time step
* `* time_scale`: Allows simulation speed control
* Result: New velocity vector for the next frame

=== Step 4: Position Update

[source,python]
----
def update(self):
    self.apply_forces()
    
    # Update position using velocity
    self.x += self.velocity.x
    self.y += self.velocity.y
    
    # Update pygame rect for collision detection
    self.rect.center = (self.x, self.y)
----

Position is updated by adding the velocity components to the current position.

== Physics Integration Flow

The complete physics integration follows this sequence:

. **Force Application**: `add_force(Vector2(0, GRAVITY * mass))`
. **Force Summation**: `total_force = Σ all_forces`
. **Acceleration**: `acceleration = total_force / mass`
. **Velocity Update**: `velocity += acceleration * DT * time_scale`
. **Position Update**: `position += velocity`

== Time Step Considerations

The simulation uses fixed time step integration:

[source,python]
----
DT = 1.0 / 60  # 16.67 milliseconds per frame
----

This ensures:
* **Frame rate independence**: Physics behave consistently regardless of actual FPS
* **Numerical stability**: Prevents large integration errors
* **Predictable behavior**: Same results across different hardware

== Scaling Factors Explained

=== Pixel Scale

`PIXEL_PER_METER = 100` means:
* 1 meter in real world = 100 pixels on screen
* A ball with radius 0.02m (2cm) = 2 pixels
* A 1m × 2m pinball table = 100 × 200 pixels

=== Time Scale

`time_scale = 1.0` provides real-time simulation. Adjusting this value:
* `time_scale = 2.0`: 2× speed for faster gameplay
* `time_scale = 0.5`: 0.5× speed for slow-motion effects
* `time_scale = 0.1`: 0.1× speed for detailed observation

== Real-World Physics Accuracy

The simulation maintains physical accuracy through:

1. **Proper force units**: Forces calculated in Newtons (N)
2. **Correct acceleration**: m/s² units maintained
3. **Time integration**: Proper Δt scaling
4. **Mass consideration**: Force scaled by object mass

This allows the simulation to use real-world constants while providing visual control through scaling factors.
